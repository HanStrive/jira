# 桌面版游戏化 Jira - 任务拆解与执行流程

## 1. 项目目标

制作一个可安装的 Windows 桌面 App，用于公司组内任务管理。应用以用户本机作为局域网服务器，组内成员安装同一个桌面端后，可连接到该服务器注册账号、登录、创建和管理任务。

应用整体体验不做传统企业后台风格，而是偏欧美卡通、游戏化、轻策略感的任务大厅。视觉参考方向是“皇室战争式的明亮、厚重、夸张、卡片化、奖章化 UI 语言”，但不会直接复制其素材、角色、图标或品牌元素。

## 2. MVP 功能范围

### 2.1 账号系统

- 用户注册。
- 用户登录。
- 用户信息包含：
  - 昵称 / 名称。
  - 头像。
  - 登录密码。
- 登录后保存本机会话，下次打开可自动进入。
- 用户头像支持两种 MVP 方案：
  - 上传本地图片。
  - 选择内置游戏化头像。

### 2.2 任务版本系统

这里的“版本号”指项目任务归属版本，例如 `1.0.1`、`1.0.2`。

- 新建版本号。
- 查看版本列表。
- 切换当前查看版本。
- 在指定版本下新建任务。
- 不同版本的任务列表相互隔离。
- 支持查看所有版本任务，或只查看当前版本任务。

### 2.3 任务管理

- 新建任务。
- 删除任务。
- 修改任务。
- 查看任务列表。
- 任务可分配给某个执行人。
- 支持查看：
  - 所有任务。
  - 我名下的任务。
  - 当前版本下的任务。
- 任务字段建议包含：
  - 标题。
  - 描述。
  - 附件：上传图片或视频，最多 5 个。
  - 所属版本。
  - 执行人。
  - 创建人。
  - 状态：待处理、进行中、已完成。
  - 优先级：低、中、高、紧急。
  - 创建时间。
  - 更新时间。

### 2.4 桌面浮窗

- 桌面右侧或右下角显示一个小浮窗。
- 浮窗显示：
  - 当前登录用户名称。
  - 当前登录用户头像。
  - 我名下未完成任务数量。
- 浮窗支持点击后打开主窗口。
- 可在设置界面选择浮窗是否显示在所有窗口最前面。
- 浮窗尽量保持轻量，不遮挡主要工作区域。

### 2.5 桌面 App 自身更新系统

这里的“版本更新系统”指桌面软件自身的更新，不是任务版本号。

MVP 建议先实现“检查更新 + 下载提示”，后续再升级为自动更新：

- 应用内显示当前 App 版本号。
- 启动时检查服务器上的最新 App 版本信息。
- 当有新版本时，在客户端弹出更新提示。
- 用户可点击下载新版安装包。
- 服务端提供一个 `latest.yml` 或 `app-update.json` 更新信息文件。

后续增强：

- 使用 `electron-updater` 实现自动下载和安装。
- 支持差量更新。
- 支持强制更新。

### 2.6 安装包与可执行文件

- 生成 Windows 安装包，格式优先选择 `.exe` Setup。
- 安装后开始菜单和桌面可出现快捷方式。
- 安装目录内有可执行 `.exe` 文件。
- 应用名称暂定：`Gorilla Jira`。

## 3. 推荐技术方案

### 3.1 桌面端

- Electron：负责 Windows 桌面 App、主窗口、浮窗、托盘、安装包。
- React + Vite：负责主界面开发。
- CSS / Tailwind 或普通 CSS：负责游戏化 UI。
- Lucide 或本地图标资产：负责基础操作图标。

### 3.2 本机服务器

- Node.js 内置服务。
- Express：提供局域网 HTTP API。
- 数据持久化建议 MVP 使用 SQLite。

选择 SQLite 的原因：

- 单机部署简单。
- 不需要安装 MySQL、PostgreSQL 等额外数据库。
- 对小团队任务系统足够。
- 数据可备份为一个 `.db` 文件。

### 3.3 服务端运行方式

应用支持两种模式：

- 服务器模式：在你的机器上启动本机服务，对局域网开放端口。
- 客户端模式：组员输入你的服务器 IP 和端口，连接到同一个任务系统。

推荐端口：

- API 服务：`37371`。
- 更新文件服务：可复用同一个 API 服务。

示例访问地址：

```text
http://你的局域网IP:37371
```

### 3.4 数据存储位置

Windows 推荐存储到用户数据目录：

```text
%APPDATA%/Gorilla Jira/
```

主要文件：

- `gorilla-jira.db`：SQLite 数据库。
- `config.json`：本机配置，包括服务器地址、是否服务器模式。
- `avatars/`：上传头像文件。
- `updates/`：新版安装包与更新描述文件。

## 4. 核心页面规划

### 4.1 登录 / 注册页

用途：

- 注册新账号。
- 登录已有账号。
- 设置服务器地址。

界面方向：

- 像游戏登录入口，不像普通后台表单。
- 中央是厚重木牌 / 金属边框面板。
- 头像选择做成英雄头像格子。
- 登录按钮做成醒目的主操作按钮。

### 4.2 任务大厅

用途：

- 查看任务总览。
- 切换版本。
- 切换“全部任务 / 我的任务”。
- 快速新建任务。

界面方向：

- 顶部是“战令 / 赛季版本”式版本选择条。
- 左侧是过滤器和成员列表。
- 中间是任务列表或任务看板。
- 右侧可显示任务详情。
- 每个任务像一张小卡牌，包含标题、优先级徽章、执行人头像、状态。

### 4.3 任务编辑弹窗

用途：

- 新建任务。
- 修改任务。
- 指派执行人。
- 修改状态和优先级。

界面方向：

- 游戏内确认弹窗风格。
- 标题、描述、版本、执行人、状态、优先级清晰排列。
- 保存按钮突出，删除按钮危险色处理。

### 4.4 版本管理弹窗

用途：

- 新建项目版本。
- 查看已有版本。
- 选择当前版本。

界面方向：

- 版本像“章节 / 赛季”卡片。
- 当前版本有高亮边框和旗帜角标。

### 4.5 用户资料页

用途：

- 查看当前账号。
- 修改昵称。
- 修改头像。
- 退出登录。

### 4.6 设置 / 更新页

用途：

- 显示当前 App 版本。
- 检查是否有新版。
- 配置服务器模式。
- 显示本机局域网 IP。
- 设置浮窗是否显示在所有窗口最前面。
- 打开数据目录。

## 5. 美术与 UI 风格规范

### 5.1 风格关键词

- 欧美卡通。
- 明亮高对比。
- 厚重按钮。
- 卡牌化任务。
- 徽章化状态。
- 轻策略游戏大厅。
- 夸张但可读。
- 有游戏感但不影响办公效率。

### 5.2 色彩方向

主色建议：

- 皇家蓝：用于主导航和版本选择。
- 金色：用于关键按钮、当前版本、高价值提示。
- 草绿色：用于完成、成功、保存。
- 红色：用于紧急、删除、阻塞。
- 深炭色：用于正文文字和暗部边框。

避免：

- 过度紫蓝渐变。
- 单一蓝色后台风。
- 太多装饰导致任务列表难扫描。

### 5.3 组件语言

- 主按钮：厚重、略带高光、底部有阴影压边。
- 任务卡：卡牌式边框，角落可放优先级徽章。
- 头像：圆形或盾牌形。
- 状态：使用徽章和颜色，不只依赖文字。
- 版本：类似赛季旗帜或章节牌。
- 弹窗：木质 / 金属 / 羊皮纸感面板，但要保持文字清晰。

### 5.4 动效原则

- 按钮点击有轻微下压。
- 新任务出现有短促弹入。
- 状态切换有徽章闪光或颜色过渡。
- 浮窗任务数变化可做轻微跳动。
- 动效保持短，不阻塞日常操作。

### 6.1 users

```text
id
name
password_hash
avatar_url
created_at
updated_at
```

### 6.2 project_versions

```text
id
name
description
is_archived
created_by
created_at
updated_at
```

### 6.3 tasks

```text
id
title
description
version_id
assignee_id
creator_id
status
priority
created_at
updated_at
```

### 6.4 task_attachments

```text
id
task_id
file_name
file_type
file_url
file_size
sort_order
created_at
```

限制：

- 每个任务最多 5 个附件。
- 附件类型支持图片和视频。
- 上传文件存放到服务器机器的数据目录中。

### 6.5 app_settings

```text
key
value
updated_at
```

建议配置项：

```text
floating_window_enabled
floating_window_always_on_top
server_mode_enabled
server_base_url
```

### 6.6 update_manifest

服务器提供 JSON 文件即可，不一定要进数据库。

```json
{
  "version": "1.0.0",
  "releaseDate": "2026-06-09",
  "notes": "首个可安装版本",
  "downloadUrl": "http://server-ip:37371/downloads/GorillaJiraSetup-1.0.0.exe",
  "force": false
}
```

## 7. API 草案

### 7.1 认证

```text

POST /api/auth/login

POST /api/auth/logout
```

### 7.2 用户

```text

```

### 7.3 任务版本

```text
GET    /api/versions
POST   /api/versions
PUT    /api/versions/:id

```

### 7.4 任务

```text
GET    /api/tasks
POST   /api/tasks
GET    /api/tasks/:id
PUT    /api/tasks/:id
DELETE /api/tasks/:id
POST   /api/tasks/:id/attachments
DELETE /api/tasks/:id/attachments/:attachmentId
```

查询参数示例：

```text
/api/tasks?versionId=xxx&scope=all
/api/tasks?versionId=xxx&scope=mine
/api/tasks?scope=mine
```

### 7.5 桌面更新

```text
GET /api/app/version
GET /api/app/update-manifest
GET /downloads/:fileName
```

## 8. 开发任务拆解

### 阶段 0：需求确认

- 确认应用名称。
- 确认是否只支持 Windows。
- 确认是否需要管理员账号。
- 确认任务是否需要评论、附件、截止日期。
- 确认同事连接服务器时是否允许手动输入 IP。

### 阶段 1：项目初始化

- 初始化 Electron + React + Vite 项目。
- 配置 TypeScript 或 JavaScript。
- 配置 Electron 主进程。
- 配置渲染进程。
- 配置开发启动命令。
- 配置打包工具 `electron-builder`。

交付物：

- 可打开的空桌面窗口。
- 可执行 `npm run dev`。
- 可执行 `npm run build`。

### 阶段 2：本机服务端

- 创建 Express 服务。
- 增加健康检查接口。
- 初始化 SQLite 数据库。
- 创建基础表结构。
- 添加服务端启动、停止、端口检查逻辑。
- 服务器模式下监听 `0.0.0.0`。
- 客户端模式下只连接远程服务器。

交付物：

- 主机可以启动 API 服务。
- 其他电脑可通过局域网访问健康检查接口。

### 阶段 3：账号系统

- 注册接口。
- 登录接口。
- 密码哈希。
- 本地 token 或 session 保存。
- 获取当前用户接口。
- 用户列表接口。
- 头像上传或内置头像选择。

交付物：

- 组员可以注册账号。
- 登录后可以看到自己的名称和头像。

### 阶段 4：任务版本系统

- 新建版本。
- 版本列表。
- 当前版本切换。
- 版本归档或删除。

交付物：

- 可以创建 `1.0.1`、`1.0.2` 等版本。
- 可以切换不同版本查看任务。

### 阶段 5：任务 CRUD

- 新建任务。
- 修改任务。
- 删除任务。
- 上传任务图片或视频附件，单个任务最多 5 个。
- 查看任务详情。
- 按版本过滤。
- 按“全部 / 我的”过滤。
- 任务分配给指定执行人。

交付物：

- 完成核心 Jira 任务管理闭环。

### 阶段 6：游戏化 UI

- 完成登录页视觉。
- 完成任务大厅布局。
- 完成任务卡牌样式。
- 完成版本选择条。
- 完成任务编辑弹窗。
- 完成头像、徽章、状态颜色。
- 加入基础动效。

交付物：

- 应用看起来像游戏公司内部工具，而不是普通管理后台。

### 阶段 7：桌面浮窗

- 创建独立浮窗 BrowserWindow。
- 浮窗置顶或靠边显示。
- 显示用户头像、名称、我的未完成任务数。
- 定时刷新任务数量。
- 点击浮窗打开主窗口。
- 支持在设置中开启 / 关闭浮窗。
- 支持在设置中开启 / 关闭浮窗置顶。

交付物：

- 桌面可见小浮窗。
- 用户可选择浮窗是否始终显示在其他窗口前面。

### 阶段 8：桌面 App 更新系统

- 设置 App 当前版本号。
- 服务端提供更新 manifest。
- 客户端启动时检查更新。
- 设置页可手动检查更新。
- 有新版本时弹窗提示下载。

交付物：

- 可以提示用户有新安装包。

### 阶段 9：安装包构建

- 配置 Windows `.exe` 安装包。
- 设置应用图标。
- 设置安装目录。
- 设置桌面快捷方式。
- 设置开始菜单快捷方式。
- 输出 setup 文件。

交付物：

- `dist/GorillaJiraSetup-x.y.z.exe`
- 安装后可从 `.exe` 启动。

### 阶段 10：局域网联调与验收

- 主机开启服务器模式。
- 主机确认防火墙端口放行。
- 同事电脑安装 App。
- 同事输入主机 IP。
- 同事注册账号。
- 同事创建、领取、修改任务。
- 主机与客户端同时查看任务变化。

交付物：

- 小组内多台电脑可共用同一套任务数据。

## 12. 风险与处理方案

### 12.1 局域网连接失败

可能原因：

- 主机防火墙未放行端口。
- 主机和组员不在同一个网段。
- 公司网络隔离。

处理方案：

- 设置页显示本机 IP 和端口。
- 提供一键复制连接地址。
- 文档中说明防火墙放行方式。

### 12.2 数据只在服务器机器上

由于使用你的本机作为服务器，数据默认存在你的电脑上。

处理方案：

- 增加数据目录入口。
- 增加手动备份数据库功能。
- 后续可迁移到 NAS、云服务器或公司内网服务器。

### 12.3 自动更新复杂度

Electron 自动更新在 Windows 上需要处理签名、发布地址和安装包格式。

处理方案：

- MVP 先做检查更新和下载提示。
- 后续再接入完整 `electron-updater`。

### 12.4 游戏化 UI 影响办公效率

过多装饰会降低任务扫描效率。

处理方案：

- 只在按钮、卡牌、徽章、版本入口和弹窗上强化游戏质感。
- 任务列表保持清晰密度。
- 颜色和动效服务状态识别，不做纯装饰堆叠。

## 13. 建议的首版交付物

首版完成后应包含：

- Windows 安装包。
- 安装后的 `.exe` 桌面程序。
- 主机服务器模式。
- 客户端连接模式。
- 注册 / 登录。
- 用户头像。
- 版本管理。
- 任务 CRUD。
- 全部任务 / 我的任务。
- 版本任务切换。
- 桌面浮窗。
- 检查更新。
- 游戏化主界面。
- 简短部署说明。
