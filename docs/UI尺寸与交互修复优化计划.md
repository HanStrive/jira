# UI 尺寸与交互修复优化计划

## 目标

当前 9:16 竖版皇室风格已经成型，但整体字号、按钮、标题、页签和图标偏大，导致信息密度低、任务列表可读空间少、部分页面像“放大版截图”。本次计划只做视觉尺寸收敛和指定交互修复，不改任务、账号、版本、垃圾桶等核心数据逻辑。

本计划覆盖：

- 登录页
- Jira 主界面
- 设置页
- 垃圾桶页
- 新建/编辑任务页
- 悬浮窗头像/昵称同步
- 昵称修改弹窗

## 总体优化原则

1. 保留皇室风格的厚边框、金色皇冠、蓝色标题条和卡通按钮质感，但降低占屏比例。
2. 9:16 主窗口尺寸不变，优先通过缩小顶部栏、标题、页签、卡片高度和按钮来增加内容区。
3. 一级标题保持有气势，但不超过界面宽度的视觉重心；二级标题、列表文字、表单标签回归工具型界面密度。
4. 高频按钮用清晰图标和适中尺寸，不再让关闭/菜单/新增按钮压过页面内容。
5. 设置页、垃圾桶页、新建任务页使用“返回”而不是“关闭”，避免用户误以为会退出整个应用。

## 需要修改的交互

### 1. 设置页、垃圾桶页、新建任务页关闭按钮改返回按钮

当前：

- `RoyalFrame` 默认右上角是红色关闭按钮，图标为 `X`。
- 设置页点击后返回项目页，但视觉上像关闭应用。
- 垃圾桶页仍在主界面容器中，右上角还是全局关闭。
- 新建/编辑任务页点击后关闭任务编辑页，但视觉上像关闭应用。

计划：

- 扩展 `RoyalFrame`，新增参数，例如 `closeMode="close" | "back"` 或 `closeIcon`。
- `closeMode="back"` 时：
  - 右上按钮改为蓝色或中性色返回按钮。
  - 图标改为 `ArrowLeft` 或 `ChevronLeft`。
  - title 改为 `返回`。
  - 点击行为仍使用当前 `onClose`。
- 应用范围：
  - 设置页：返回主界面。
  - 垃圾桶页：返回项目任务列表，并恢复 `scope=all/status=all`。
  - 新建任务页/编辑任务页：返回任务列表。
- 主界面和登录页仍保留红色关闭按钮，用于退出应用。

### 2. 修改头像后同步更新悬浮窗头像

当前问题：

- 设置页上传头像后会更新主窗口用户状态。
- 悬浮窗没有使用主进程已有的 `floating:stats` 数据。
- 悬浮窗头像使用 `user?.avatarUrl`，没有拼接 `serverBaseUrl`，当头像地址为 `/avatars/...` 时容易显示失败。
- 主窗口和悬浮窗之间没有用户资料更新事件。

计划：

- 悬浮窗头像渲染改为 `absoluteUrl(serverBaseUrl, user?.avatarUrl)`。
- `FloatingApp` 接入 `window.gorilla.onFloatingStats`，用主进程推送的 `stats.user` 和 `stats.myOpenTasks` 更新头像、昵称、任务数。
- 增加轻量 IPC：
  - preload 暴露 `notifyUserChanged(user)` 和 `onUserChanged(callback)`，或复用一个 `user:changed` 广播。
  - `handleUserUpdated(nextUser)` 保存本地用户后主动通知所有窗口。
- 上传头像成功后立即刷新：
  - 主窗口用户头像。
  - 设置页头像。
  - 悬浮窗头像。
  - 用户列表中的当前用户头像，避免任务执行人头像仍旧。

### 3. 修改昵称点击没反应，改为应用内小窗口

当前问题：

- 设置页“修改昵称”使用 `window.prompt`。
- 在 Electron 无边框窗口下，系统 prompt 样式不统一，也可能被窗口焦点/置顶关系影响，用户感觉“没反应”。

计划：

- 新增 `RenameUserDialog` 应用内弹窗：
  - 皇室风格小面板。
  - 标题：`修改昵称`。
  - 输入框默认填当前昵称。
  - 字数限制建议 2-16 个字符。
  - 按钮：`取消`、`保存`。
  - 回车保存，Esc/取消关闭。
  - 昵称为空或未变化时禁用保存。
- 保存成功后：
  - 调用现有 `/api/users/me`。
  - 更新主窗口 `user`。
  - 更新 `localStorage`。
  - 通知悬浮窗更新昵称。
  - 刷新用户列表和任务列表中执行人展示。

## 具体执行步骤

### 第一步：建立全局尺寸变量

在 `src/renderer/styles.css` 的皇室 UI 区域增加统一变量，减少后续尺寸散落：

```css
:root {
  --royal-frame-header-h: 68px;
  --royal-title-size: 28px;
  --royal-section-title-size: 19px;
  --royal-body-text-size: 15px;
  --royal-card-title-size: 17px;
  --royal-icon-button: 44px;
  --royal-card-radius: 8px;
}
```

再逐步替换关键尺寸，避免每个页面单独调导致风格不一致。

### 第二步：收敛全局框架

修改目标：

- `.royal-frame` 行高：`86px 1fr 42px` 改为约 `68px 1fr 32px`。
- `.royal-frame-tab` 高度从 104px 降到 76-82px。
- `.royal-frame-tab strong` 从 36px 降到 26-28px。
- `.royal-frame-crown` 从 104x84 降到 78x62。
- `.royal-square-button` 从 55x55 降到 42-46px。
- `.royal-frame-body` 外边距/内边距从 18px 降到 10-12px。

验收：

- 顶部不压内容。
- 标题不被皇冠挡住。
- 右上按钮仍易点击。
- 页面整体仍像游戏 UI，而不是普通后台。

### 第三步：逐页调尺寸

登录页：

- 收敛标题、徽章、输入框、登录/注册按钮。
- 保持服务器地址、账号、密码三块清晰。
- 输入文字不能被右侧下拉/眼睛图标遮挡。

主界面：

- 项目英雄区高度从约 164px 降到 110-125px。
- 页签高度降到 44-50px。
- 任务列表标题条降到 48-54px。
- 任务卡片降到 58-64px，保证 9:16 下至少能看到 5-7 条任务。
- 菜单弹层缩小，菜单顺序保持：`设置`、`垃圾桶`、`退出登录`。

设置页：

- 分组标题条、卡片、开关整体缩小。
- 目标是在 9:16 默认窗口下，账号信息、通用设置、关于三组尽量一屏可见。
- 修改头像、修改昵称仍有足够点击区域。

垃圾桶页：

- 复用主界面收敛后的项目头和列表密度。
- 顶部红色关闭改返回按钮。
- “返回项目”按钮从提示条中移除或弱化，避免重复入口。
- 恢复/彻底删除按钮保持清晰但缩小。

新建/编辑任务页：

- 顶部红色关闭改返回按钮。
- 表单字段卡片和标签缩小。
- 标题、描述、附件、执行人、版本号、紧急程度、状态都要能在竖屏中顺畅滚动。
- 底部主按钮缩小但保持主操作地位。
- 附件缩略图、文件名、删除按钮保持清楚。

悬浮窗：

- 先修同步问题。
- 如果主窗口整体缩小后悬浮窗显得突兀，再把头像从 82px 降到 68-72px，数字角标从 30px 降到 24-26px。

### 第四步：实现返回按钮能力

涉及组件：

- `RoyalFrame`
- `JiraHomePage`
- `SettingsPanel`
- `TaskEditorPage`

建议实现：

- `RoyalFrame` 增加 `closeMode` 参数。
- `closeMode="back"` 使用 `ArrowLeft` 图标和中性色按钮。
- `SettingsPanel` 和 `TaskEditorPage` 传入 `closeMode="back"`。
- `JiraHomePage` 在 `activePanel === "trash"` 时传入 `closeMode="back"`，否则默认关闭。

### 第五步：实现昵称修改弹窗

新增组件：

- `RenameUserDialog`

状态放在：

- `SettingsPanel` 内部维护 `renameOpen` 和 `draftName`。

替换：

- 移除 `window.prompt`。
- 点击“修改昵称”打开弹窗。

验收：

- 点击修改昵称立即出现弹窗。
- 输入新昵称保存后，设置页、主界面、悬浮窗同步更新。
- 取消不会修改数据。

### 第六步：修复头像/昵称悬浮窗同步

涉及文件：

- `src/renderer/main.jsx`
- `src/main/preload.js`
- `src/main/main.js`

建议实现：

- `FloatingApp` 使用 `absoluteUrl(serverBaseUrl, user?.avatarUrl)`。
- `FloatingApp` 使用 `onFloatingStats` 接收主进程定时推送。
- 新增 `user:changed` IPC，用于头像/昵称更新后立即推送。
- `handleUserUpdated` 中：
  - `setUser(nextUser)`
  - `saveJson(USER_KEY, nextUser)`
  - 通知其他窗口用户已变化
  - 刷新 `users/tasks`，保证执行人信息同步

验收：

- 设置页上传头像后，悬浮窗头像立即变化。
- 设置页修改昵称后，悬浮窗昵称立即变化。
- 重启应用后头像和昵称仍正确。

## 验收清单

功能验收：

- 登录页可以正常登录/注册。
- 主界面任务列表显示更紧凑，不再只露出少数几条。
- 主界面菜单可以打开设置、垃圾桶、退出登录。
- 设置页右上角为返回按钮，不是关闭按钮。
- 垃圾桶页右上角为返回按钮，不是关闭按钮。

- 任务列表卡片高度更短，状态标签和删除按钮不挤压标题。

技术验收：

- `node --check src/main/main.js`
- `node --check src/main/preload.js`
- `npm run build`
- 运行 `scripts/capture-ui.js` 重新生成截图。
- 如需要发布，再执行 `npm run dist` 生成新版安装包。

## 不在本次修改范围

- 不修改数据库结构。
- 不修改服务端端口和局域网注册/登录逻辑。
- 不重新设计任务字段。
- 不改变 15 天垃圾桶删除规则。
- 不改变主窗口 9:16 竖版定位。
- 不重做美术资源，仅优化现有 CSS 和交互。
